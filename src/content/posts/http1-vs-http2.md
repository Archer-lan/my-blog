## 一、HTTP/1.0：短连接时代

### 核心特性

- **无状态与无连接**：每个 TCP 连接只能发送一个请求，服务器响应后立即断开。频繁的三次握手带来明显开销。
- **性能瓶颈**：无法复用连接。加载大量资源（如图片）时需要不断建立/关闭 TCP 连接，并受 **TCP 慢启动（Slow Start）** 影响，传输效率低。

### 补充：可用但不彻底的优化

- HTTP/1.0 可通过 `Connection: keep-alive` 复用连接，但属于**非标准扩展**，兼容性不稳定；同时仍然无法解决**串行请求**问题。

## 二、HTTP/1.1：持久连接与标准化

### 1）持久连接（Persistent Connection）

- 默认开启 `keep-alive`。
- **Pipeline（管道化）**：客户端可以连续发送多个请求，不必等待上一个响应返回。
  - **注意**：服务器仍必须**按顺序**返回响应，因此会出现**应用层队头阻塞（Head-of-Line Blocking）**。

### 2）更精细的缓存管理

- `Cache-Control`（如 `max-age`）比 1.0 的 `Expires` 更灵活。
- 引入 **ETag / If-None-Match**，支持基于特征值的强校验。

### 3）带宽优化（Range）

- 支持断点续传：通过 `Range` 请求部分资源。
- 返回状态码：**206 Partial Content**。

### 4）虚拟主机支持（Host）

- 请求必须包含 `Host` 头，使同一 IP 可根据域名路由到不同站点（对 CDN / 云服务很关键）。

## 三、HTTP/2：二进制分帧的飞跃

### 1）二进制分帧（Binary Framing Layer）——基石

- HTTP/2 在应用层与传输层之间引入**分帧层**。
- 将原本的文本报文拆分为 **HEADERS 帧** 与 **DATA 帧**。

### 2）多路复用（Multiplexing）——解决应用层阻塞

- **流（Stream）**：同一连接中并行存在多个双向流，每个流有唯一 ID。
- **帧（Frame）**：最小传输单位。帧携带 Stream ID，即使乱序到达也可正确重组。
- **效果**：在**一个 TCP 连接**上并行发送请求/响应，消除 HTTP/1.1 Pipeline 的**应用层队头阻塞**。

### 3）头部压缩（HPACK）——减少冗余

- 静态表（常用头预定义）+ 动态表（连接过程中动态更新）。
- 使用 **Huffman 编码**压缩字符串；对重复且较长的字段（如 `User-Agent`）收益明显。

### 4）服务器推送（Server Push）

- 服务器通过 `PUSH_PROMISE` 告知客户端"即将推送这些资源"。
- **局限**：推送过多可能抢占带宽。实践中更常用 `<link rel="preload">` 进行精细控制。

## 四、核心对比总结

| 特性 | HTTP/1.0 | HTTP/1.1 | HTTP/2 |
| --- | --- | --- | --- |
| 连接方式 | 短连接（默认） | 长连接（默认） | 长连接（单连接多路复用） |
| 传输形式 | 文本（Text） | 文本（Text） | 二进制分帧（Binary） |
| 阻塞处理 | 串行处理、排队 | 管道化但仍有应用层队头阻塞 | 多路复用，消除应用层队头阻塞 |
| 头部控制 | 简单 | 仍为明文头部 | HPACK 头部压缩 |
| 缓存能力 | Expires | Cache-Control、ETag | 沿用 1.1（并结合多路复用改善体验） |
| 新增能力 | - | Range、Host 等 | Server Push、请求优先级等 |

## HTTP/3：彻底告别延迟的"新基建"

### 1. 为什么要有 HTTP/3？（解决 TCP 的"心病"）

虽然 HTTP/2 解决了应用层的队头阻塞，但它依然跑在 **TCP** 协议上。TCP 有一个天生的弱点：它必须保证数据的严格顺序。

- **TCP 队头阻塞**：如果一个 TCP 数据包在传输中丢失，即便后续的数据包已经到达，接收端也必须等那个丢了的包重传成功后，才能把数据交给应用层。
- **连接建立慢**：建立一个加密的 HTTP/2 连接，需要先进行 TCP 三次握手，再进行 TLS 握手，来回往返多次（RTT），响应会有明显的延迟。

### 2. QUIC 协议：HTTP/3 的核心发动机

HTTP/3 选择跑在 **UDP** 之上，并重新定义了可靠性。它就像是给轻便的 UDP 穿上了一层"可靠性装甲"：

- **真正的多路复用**：在 HTTP/3 中，不同的流（Stream）之间是**完全独立**的。如果流 A 丢包了，只会阻塞流 A，流 B 和流 C 依然可以正常传输。这彻底解决了 TCP 层的队头阻塞问题。
- **极速连接（0-RTT）**：它将传输连接和加密握手合并在一起。对于之前访问过的网站，HTTP/3 可以实现 **0-RTT** 启动，即数据可以和握手信息一起发送，网页几乎秒开。
- **连接迁移**：这是移动时代的神技。以往当你从 Wi-Fi 切换到 4G 时，IP 地址变了，TCP 连接必须断开重连。但 HTTP/3 使用的是"连接 ID"，只要 ID 不变，即使网络环境切换，连接也不会中断，打游戏或看视频时完全感觉不到卡顿。
