## Commands

```bash
pnpm dev           # Astro dev server — fast, but search will not work until index exists
pnpm dev:search    # One-shot: builds the site + writes a Pagefind index to public/pagefind/
                   #   Run this once after editing posts when you want search to work in dev.
pnpm build         # astro build + pagefind --site dist (production output to dist/)
pnpm preview       # Serve dist/ exactly as GitHub Pages will
pnpm astro check   # Type-check .astro and .ts files
```

`public/pagefind/` is gitignored — it's a dev-only artifact regenerated by `pnpm dev:search`.

Deploys happen automatically on push to `main` via `.github/workflows/deploy.yml` (build + Pagefind index → upload `dist/` → GitHub Pages). Live URL: `https://archer-lan.github.io/my-blog/`.

## Astro base path is `/my-blog`

`astro.config.mjs` sets `site: 'https://archer-lan.github.io'` and `base: '/my-blog'`. Every internal link must include this prefix — **never hardcode paths starting with `/`**. Use:

- `import.meta.env.BASE_URL` (always ends with `/`) for one-off references
- `localizedHref(locale, path)` from `src/i18n/index.ts` for any link in a page or component (this also handles the `/en/` prefix)

## i18n architecture

Two locales: `zh` (default, no URL prefix) and `en` (`/en/` prefix). The defaults assume `zh`; pass `locale` explicitly everywhere.

- **Translation strings**: `src/i18n/{zh,en}.ts` implement the `Dict` interface in `src/i18n/types.ts`. `t(locale)` returns the right bundle. To add a UI string, add it to the `Dict` type first (typescript will then force both zh and en to fill it in).
- **URL helpers**: `localizedHref(locale, path)` and `getLocale(url)` in `src/i18n/index.ts`. `localizedHref` already includes the `/my-blog` base.
- **Page mirroring**: every Chinese page under `src/pages/` has an English counterpart under `src/pages/en/`. They're near-identical except for `const locale: Locale = 'zh' | 'en'`. Keep both in sync when adding features.
- **Post filtering**: posts live in one collection (`src/content/posts/`) with a `lang` frontmatter field. `getPublishedPosts(locale)` / `getTagGroups(locale)` / `getCategoryGroups(locale)` filter by it.
- **Translation linking**: an English post can reference its Chinese counterpart via `translationOf: <zh-slug>` in frontmatter. `findTranslation(post)` returns the pair; `PostLayout` only renders the lang-toggle when a pair exists.

## Content Collections

Schema in `src/content.config.ts` (zod). Key fields: `title`, `date`, `description`, `category`, `tags[]`, `cover?`, `draft?`, `pinned?`, `readingTime?`, `lang`, `translationOf?`. Draft posts are excluded in production (`import.meta.env.PROD`) but visible in dev.

Reading time is auto-estimated by `estimateReadingTime()` in `src/lib/posts.ts` if the frontmatter omits it — it counts CJK chars and Latin words separately.

## Pagefind search — the Blob-URL workaround

Pagefind ships as ES modules in `dist/pagefind/` (and `public/pagefind/` for dev). Vite refuses to let source code dynamically `import()` files from `public/`. The workaround in [src/components/SearchModal.astro](src/components/SearchModal.astro):

1. `fetch()` `pagefind.js` as text (Vite serves it as a static asset)
2. Rewrite every occurrence of `import.meta.url` in the source to a hardcoded absolute URL pointing at the real `pagefind.js` location — Pagefind uses `import.meta.url` to resolve `pagefind-entry.json` and the wasm files relative to itself; Blob URLs don't support relative resolution so this rewrite is required
3. Wrap the rewritten code in a Blob, `import()` the Blob URL

If you ever upgrade Pagefind and search breaks with "Failed to load Pagefind metadata" or "Unexpected token '<'", suspect this rewrite first.

## Styling

Tailwind v4 with `@tailwindcss/vite`. Design tokens are defined in [src/styles/app.css](src/styles/app.css) under `@theme` — zinc-based dark background, cyan/emerald/amber accents, Inter + Noto Sans SC. The `.prose-article` class customizes `@tailwindcss/typography` for article bodies (headings, code blocks, blockquotes). Dark mode is class-based (`.dark` on `<html>`) with a `@custom-variant`.

The FOUC-prevention theme script lives inline in `BaseLayout.astro` — it runs before any CSS to set the `dark` class from `localStorage.theme` or system preference.

## Layouts feed locale down

`BaseLayout` takes `locale`, computes `dict = t(locale)`, and passes it to `Navbar` / `Footer` / `SearchModal`. `PostLayout` wraps `BaseLayout` and additionally accepts `headings`, `prev`/`next`, and an `altLocaleHref` for the lang toggle. When building a new page-type layout, follow this pattern — read `locale` once, pass `dict` to child components.

## Giscus is gated on config

[src/config.ts](src/config.ts) exports `GISCUS` with empty `repoId` and `categoryId` placeholders. [src/components/Giscus.astro](src/components/Giscus.astro) calls `isGiscusEnabled()` to decide whether to render the script or a placeholder hint. When the user provides their giscus.app `<script>` snippet, copy `data-repo-id` and `data-category-id` into `GISCUS` — nothing else needs to change.

The Giscus component also installs a `MutationObserver` on `<html>` to forward theme changes to the giscus iframe via `postMessage`.

## pnpm quirks

- `pnpm-workspace.yaml` has `allowBuilds: { esbuild: true, sharp: true }` — required by pnpm 11 to allow these native postinstall scripts to run. Without it, `pnpm install` will warn and Astro's image pipeline (sharp) and dev server (esbuild) break.
- `tsconfig.json` excludes `public/pagefind` because TypeScript would otherwise try to type-check Pagefind's minified ESM and produce thousands of false errors.

## Adding a new post (zh + optional en)

1. Create `src/content/posts/my-post.md` with required frontmatter (see existing posts for shape).
2. For an English version: `src/content/posts/my-post-en.md` with `lang: en` and `translationOf: my-post`.
3. `git push` — CI builds and deploys. To preview locally with search, run `pnpm dev:search` before `pnpm dev`.

## Adding a new page that should be available in both locales

1. Create `src/pages/foo.astro` (zh).
2. Mirror it at `src/pages/en/foo.astro` with `const locale: Locale = 'en'`.
3. Internal links from anywhere else go through `localizedHref(locale, '/foo')`.
4. If the page needs UI text, add the strings to `Dict` in `src/i18n/types.ts` and fill both `zh.ts` and `en.ts`.
